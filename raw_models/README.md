# Asset pipeline

Builds `public/anatomy.glb`, `public/skeleton.glb` and `public/mesh_mapping.json` from two open datasets.

## Raw data (gitignored)

| Path | Source |
|---|---|
| `raw_models/bp3d/isa_BP3D_4.0_obj_99/` | [BodyParts3D](https://lifesciencedb.jp/bp3d/) 4.0 OBJ files ("is-a" tree, 99% quality). Unzip `isa_BP3D_4.0_obj_99.zip` here. |
| `raw_models/z-anatomy/extracted/Z-Anatomy/Startup.blend` | [Z-Anatomy](https://www.z-anatomy.com/) Blender file (from `Z-Anatomy.zip`) |
| `raw_models/z_anatomy_exports/` | Generated by `export_z_anatomy.py` (step 2 below) |

`parts_list.txt` (the BodyParts3D parts index) is committed.

## Requirements

- [uv](https://docs.astral.sh/uv/) (installs Python 3.13 and the pinned packages from `pyproject.toml` / `uv.lock`)
- [Blender](https://www.blender.org/) 4.x or 5.x, only for step 2
- Node/npm (repo root `npm install`), for the final glTF Transform compression

## Build

```bash
cd raw_models

# 1. Choose which BodyParts3D meshes to ship (only needed when changing the selection).
#    Writes muscle_files.json -> filtered_muscles.json, and bone_files.json. All three are committed.
uv run python find_muscles.py && uv run python filter_muscles.py && uv run python find_bones.py

# 2. Export Z-Anatomy meshes (extra muscles + registration landmarks) to z_anatomy_exports/.
blender -b --factory-startup --python export_z_anatomy.py

# 3. Build the GLBs (about a minute).
uv run python -m pipeline.build
```

From the repo root, step 3 is also `npm run assets:build`.

Useful flags: `--only anatomy|skeleton`, `--no-refine` (skip subdivision/smoothing), `--density 2.2` (more triangles).
Reports land in `raw_models/build/`: `registration.json` (alignment residuals) and `report.json` (per-mesh faces
and dropped fragments). Tests: `uv run pytest`; lint/format: `uv run ruff check` / `uv run ruff format`.

## What the pipeline does (`pipeline/`)

1. **Registration** (`register.py`). Z-Anatomy and BodyParts3D come from different bodies and coordinate frames.
   Instead of hand-tuned offsets, a similarity transform (rotation, uniform scale, translation) is fitted with trimmed
   ICP over 32 landmark structures that exist in both datasets (long bones, pelvis, skull bones, several large
   muscles), matched by name. Median landmark distance: 5.5 mm (old offsets) → 3.3 mm.
2. **Cleanup** (`geometry.py`). Merge vertices, drop degenerate/duplicate faces and tiny stray fragments (BodyParts3D
   meshes carry up to 170 specks each; each removed one is < 1% of its mesh's area and < 60 triangles), repair
   non-manifold edges, orient faces consistently.
3. **Refinement**. BodyParts3D meshes are coarse (median ~2.3k triangles, ~8 mm edges) and faceted from MRI
   segmentation: one Loop subdivision + Taubin smoothing (volume-preserving) gives smooth surfaces. Z-Anatomy meshes
   are already smooth and skip this.
4. **Size-aware simplification**. Quadric edge collapse down to `1.6 × area_mm² ^ 0.75` triangles (300–14k), so large
   muscles keep smooth silhouettes and small ones stay cheap. Result: ~987k triangles total (was 1.6M).
5. **Fibre field** (`fibers.py`). For every muscle and tendon, a harmonic field between its two ends (cotangent
   Laplace solve) whose surface gradient gives a smooth per-vertex fibre direction that follows fan-shaped muscles.
   Stored as the `_FIBER` vertex attribute; the viewer renders striations along it.
6. **GLB + compression** (`glb.py`, `build.py`). One named node per structure (extras: `kind`, `source`, `fmaId`),
   then glTF Transform Meshopt compression with quantization (16-bit positions over the whole body ≈ 0.03 mm).
